## 必需环境

- 每次验收生成唯一 `challengeDigest`；device/client attestation 都必须匹配该 challenge、待发布 `sourceCommit` 和证据时间窗，不能复用另一版本或另一轮验收的文件；
- 至少 2 台真实 Windows 设备。每台设备必须有唯一的 64 位小写 SHA-256 匿名 ID、`physical: true`、Windows build、架构和独立 `t8-collaboration-device-attestation-v1` JSON；不得写入真实机器名、用户名或硬件序列号；
- 至少 3 个独立客户端。每个客户端必须有唯一匿名 ID、唯一 profile ID、唯一 session digest、所属设备、`chrome`/`edge`/`electron` 类型和独立 `t8-collaboration-client-attestation-v1` JSON；至少跨两台设备并覆盖 Chrome 与 Edge；
- 使用公共 DNS 主机名、路径以 `/collab` 结尾的 HTTPS Base URL；
- TLS、SNI、证书主机名、WebSocket Upgrade 和 Range 均经真实代理验证。

设备 attestation 与客户端证据必须是不同 artifact，且 F8 检查必须通过 `subjectDeviceIds` / `subjectClientIds` 明确引用实际参与者及其 artifact。单个 combined report 不能再冒充全部独立设备和客户端。

## 安全采集 attestation

项目提供 `collaboration:evidence:attest`，只生成匿名 attestation，不组装结果、不替测试标记 `passed`：

```text
npm run collaboration:evidence:attest -- challenge

npm run collaboration:evidence:attest -- device \
  --challenge <同一轮challengeDigest> \
  --source-commit <待发布40位commit> \
  --physical-confirmed \
  --out <device-a.json>

npm run collaboration:evidence:attest -- client \
  --device-attestation <device-a.json> \
  --browser <chrome|edge|electron> \
  --session-digest <仅SHA-256摘要> \
  --out <client-a.json>
```

- `device` 必须在真实 Windows 上运行并显式确认物理设备；平台、架构和 Windows build 由本机读取，匿名 device ID 使用安全随机数生成。
- `client` 从已验证的 device JSON 继承 challenge、source commit 和 device ID，并随机生成匿名 client/profile ID；只接受 64 位小写 session SHA-256，不接受 Cookie、session 原值、profile 路径、机器名或硬件序列号。
- 输出父目录必须是普通目录；文件使用独占创建，已存在时拒绝覆盖。控制台只返回文件名、匿名 ID、字节数和 SHA-256，不回显绝对路径或 session digest。
- 同一轮的两台设备使用同一个 challenge/source commit；每个真实客户端分别执行一次 `client`。session 摘要应由 QA harness 在内存中计算，不要把原始 Cookie 写入命令行、日志或证据目录。

## 必需检查

清单必须把以下每项标记为 `passed`，附完成时间、至少一个证据文件和对应指标：

- 局域网三客户端：跨两台设备，覆盖同时拖动不同/同一节点、同时文本编辑、删改竞争；静默丢失、删除复活和旧运行结果串写必须均为 0；
- 断网至少 60 秒：至少两个客户端跨两台设备参与，记录恢复客户端和补齐 operation gap 数量，三个数据完整性计数仍必须为 0；
- 主机重启及 backup 恢复：至少三客户端重新连接，`quick_check` 成功、外键违规为 0，且没有静默丢失/复活/旧结果串写；
- Electron 在两台设备完成安装、升级、降级拒绝、`better-sqlite3` 加载和数据迁移；
- Chrome、Edge 各自记录通过场景数和 0 个非预期错误；
- 公网 health 必须是 TLS 授权、公共 DNS、10 秒内的 HTTP 200；邀请至少有成功兑换、重放拒绝和过期拒绝；WebSocket 必须得到 101、三个客户端 join 且非预期关闭为 0；
- 至少 100 MiB 上传必须完成并验证 SHA-256、非预期错误为 0；Range 拖播必须在同等规模文件上获得 206/partial response 并完成 seek；
- 登录、消息、上传、下载四类限速及稳定 Retry-After/关闭语义；
- reviewer 越权、私有接口、路径/MIME/压缩炸弹、SSRF/深 JSON、重放、敏感日志红队；
- 连接负载至少达到 100 个峰值连接且非预期断开为 0；操作吞吐至少 10,000 条、持续至少 100 ops/s 且非预期错误为 0；另需 10 万素材索引和带观测字节/时长的存储增长预算。

单元测试或本机回环只能作为附加证据，不能填充真实设备、公网 TLS/SNI 或生产代理项目。不得手工把未执行项目改写为 `passed`。
