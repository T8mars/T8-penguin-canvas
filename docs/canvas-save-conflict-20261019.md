# 画布保存冲突修复

2026-10-19：开发修复与限定验证已完成，尚未打包或发布。产品版本保持 v3.3.5；其已发布 Tag 和安装包不变。

## 原因

提示中的“版本”是画布内容的保存序号 revision，不是软件版本。后台结果写入、其他窗口或其他客户端可以先更新同一画布。旧序号保存被 CAS 比较并交换保护拒绝，是为了避免覆盖较新的内容，单凭截图不能认定是用户误操作，也不能确认该用户现场的具体写入来源。

旧自动保存流程把 HTTP 409 直接标为永久冲突，没有先取最新权威文档并区分“只有保存序号变化”和“同字段确实冲突”；普通画布又缺少明显的处理入口。另一个生命周期问题是切换画布会重建带 key 的编辑器，而未完成的保存仍可能返回：关闭观察器和恢复状态不能跟着旧编辑器失效。

## 修复合同

1. 仅对明确的 `revision_conflict` 读取最新权威文档，使用原始基线、本地最新草稿和权威内容三方合并。互不冲突的字段自动合并，随后仍由原有串行 CAS 自动保存确认；GET 或队列清空不视为已保存。
2. 自动恢复每画布最多两次，单次权威 GET 截止五秒。持续争抢、网络失败、无有效基线、序号倒退或新状态已取代旧请求时，不盲写、不无限重试。用户可显式安全重试；不会重放生成请求。
3. 同字段修改、删除与编辑冲突继续阻止覆盖。画布顶部直接提供同步重试、下载未保存本地副本、保留本地并合并、采用服务端版本。后两者需再次确认；取消不改本地内容，确认期间的新编辑仍保留。
4. 恢复预算、单飞请求和待保存状态由外层共享运行时持有；迟到的旧编辑器响应只更新共享状态，当前编辑器负责呈现。关闭守卫位于 keyed 编辑器外，切换期间不产生虚假的“干净”回执。
5. 关闭时发现离屏真冲突，返回对应画布显示入口；离屏无冲突合并草稿则重新激活，沿用正常加载与 CAS 队列保存后才能批准关闭。实际运行任务、未保存内容和失败仍阻止关闭。
6. 同一显示 ID 被另一 `entityUid` 替换时，不将旧节点或连线的本地修改拼到新实体上；双方都有修改则明确标记身份冲突。

不关闭 CAS、不强制退出、不覆盖用户数据库，也不回滚 revision、ACK 或 schema 恢复保护。普通生成和 Strata 服务未改动。

主线程另复现两类交互问题，合计确认并修复五类，未把分支漏修重复计数：

- 手动处理冲突的 GET 期间切走再切回，响应仍提交给旧编辑器，提示不消失，当前内容没有跟随确认选择。两种确认均改由当前编辑器提交；期间新编辑和服务端非冲突字段继续保留。
- 焦点在顶部冲突控件时，窗口捕获阶段仍执行复制或粘贴，先于控件的停止冒泡。捕获处理器现在识别该控件区域，不执行背后画布剪贴板命令；普通画布快捷键不变。

独立审查的三个问题分别由当前编辑器保存通知、无基线新实体身份隔离、成功删除通知及运行时退休修复。删除失败不退休；分页目录缺项或未知 GET 404 不授权丢弃草稿。退休门覆盖旧自动保存成功和失败、恢复及权威提交，禁止迟到响应重新写回待保存状态。所有补偿仍走原有自动保存 CAS 队列。

## 交付边界

需要新版本安装包才能让用户获得修复。当前用户机器、多个真实设备并发和安装版升级尚未复验；本次没有生产 build、版本升级、推送、Tag 或 Release。不得据此宣称所有现场冲突来源已消失，真实同字段竞争仍必须保留明确选择，不能用最后写入覆盖来隐藏问题。
