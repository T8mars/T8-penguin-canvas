# 启动日志保存

2026-10-08：日志采集与导出已随v3.2.8双平台发布，见[发布记录](release-v3.2.8.md)；该发布没有修改启动和名称逻辑。随后据用户日志完成的独立修复见[启动修复专题](startup-history-fix-20261008.md)，已随[v3.2.9双平台发布](release-v3.2.9.md)。

## 用户操作

右上角设置 → 启动诊断 → **保存启动日志** → 选择保存位置。把生成的 `t8-startup-*.log` 文件发给作者即可，不需要查找数据库或自行改路径。取消保存不算成功；保存失败会提示重试。

桌面版从程序启动开始自动采集，在默认 Electron `userData/logs/startup/` 内保留 `startup-current.jsonl` 和 `startup-previous.jsonl` 两次启动记录。此路径属于桌面日志，不随项目数据目录迁移。每次记录最多 512 个事件、单文件小于 256 KiB；异步写入，不新增数据库初始化或目录扫描。磁盘写入失败时，本次记录仍可从内存导出，但重启后不能保证留存。突然终止进程时尚未完成的异步日志可能丢失。

导出包含软件/运行时版本、平台、启动时间，以及 Electron、后端、数据库现有启动阶段计时和前端连接/目录/文档/编辑区阶段。前端变化事件的 `phaseMs` 是上一阶段持续时间；`elapsedMs` 是从前端启动到当前事件的累计时间。前十五分钟检测前端事件循环长延迟，异常只记录固定阶段标识，不保存错误原文。

仅从既有 `[startup]` 计时行中提取白名单字段。API Key、Cookie、令牌、URL、文件路径、提示词、画布名称/ID、节点和素材内容、普通业务日志及错误堆栈均不保存。旧日志重新导出也经过同样过滤。

导出通过受信任主窗口/主 frame 的最小 IPC 打开原生保存框，不依赖数据库读取成功。主进程仍被同步任务阻塞时，保存框要等主进程恢复后才能响应；本轮日志功能不解决该阻塞。网页模式只下载本次前端记录，明确标为 `renderer-only`，不冒认为完整桌面启动日志。

- 新专项 `tests/startupDiagnostics.test.cjs`：17/17，覆盖真实临时文件写入/两次启动保留、字段过滤/容量上限、磁盘失败、实际 IPC 处理器的授权/取消/错误/重复点击、生产前端保存处理器和前端计时/网页下载；包含新模块针对实际 IPC 类型声明的专项语义检查。
- 相邻 `canvasCatalogStartupUi.test.cjs`：5/5；`electronPackaging.test.ts` 与 `apiSettingsTheme.test.ts`：31/31。中英文 4911 条目检查通过，包装声明、语法、差异与两份保护文件散列通过。
- 完整 `tsc --noEmit` 此前在768MiB下内存耗尽；后续当前授权的正式发布使用既有Node3GiB配置，生产 `tsc -b` 和Vite实际通过。两者是不同场景，不把前次失败抹掉；新模块专项语义检查通过。
- 文件测试仅使用新建系统临时目录，未读取用户或历史数据库，无付费API调用。Windows唯一一次构建及同源Mac发布完成；Electron原生对话框、安装版用户现场和视觉交互仍按授权后补、不视为通过。旧Tag不移动。
