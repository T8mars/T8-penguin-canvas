# 自动更新退出停在“正在保存”

2026-10-21：已随 v3.3.8 同源双平台发布，六资产独立完整回下载通过；固定源码/Tag与发布事实见[发布专题](release-v3.3.8.md)。旧 v3.3.6 / v3.3.7 安装包和 Tag 不变。

## 现场与确定的代码缺陷

- 本机运行安装版 v3.3.6，更新器日志确认 v3.3.7 已下载，尚未出现 `quitAndInstall`；后台监听已关闭。没有读取用户数据库，也没有强杀程序。
- 现有现场日志没有保存后台关闭步骤，不能断言当次卡在哪个后台任务。
- 源码确认：15 秒有界关闭结果被缓存为最终回执；实际关闭随后完成也不会推进更新。保存成功后的全屏输入保护只显示“正在保存”，错误状态则位于保护层下面，造成无限等待的表象。

## 修复合同

1. 保留实际后台关闭 Promise 与独立完成标志，不把短截止当作真实存储完成回执。先完成原 CAS 保存确认，再启动关闭；原后台工作不重启、不复制。
2. 更新在 15 秒截止后再有界等待原关闭工作最多 105 秒；完成即自动启动一次原平台更新器。直到真实存储生命周期完成，绝不启动安装器、不释放编辑保护。
3. 真正超时/异常显示只读故障面板，不再显示“正在保存”；可从面板导出本机诊断、显式继续等待/重试原安装流程。后续关闭完成时可重试，不重复下载、不自动重放安装失败。
4. 固定阶段通过当前已批准 requestId 的 IPC 传递，忽略旧请求、未批准回执、取消后的事件和非白名单值。显示保存、后台关闭、较长等待、安装和失败；中英文同步。
5. 后台关闭按 HTTP、恢复器、预览、视频、协作、语义、延迟工作和数据库记录固定阶段。复用两会话、有界、脱敏的本机诊断导出，并写入原更新日志；不记录画布、密钥、URL、路径或原始错误文本。诊断失败不能中断安全退出。
