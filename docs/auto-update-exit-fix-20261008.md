# 自动更新保存/退出冲突修复

2026-10-08：开发修复和限定验证完成；用户随后明确授权 v3.3.0 打包发布，当前事实见[发布专题](release-v3.3.0.md)。现有 v3.2.9 Tag、Release 和安装包保持冻结。

## 已确认的问题与现场边界

- 当前 `electron-updater` 的 Windows `BaseUpdater.quitAndInstall()` 先启动 NSIS，再请求 `app.quit()`；本项目退出必须先等画布保存回执，再关闭后台和数据库。默认 NSIS 很快尝试强制结束同名程序，存在更新安装与正常保存/释放文件的竞态。
- 同一句 `appCannotBeClosed` 还出现在旧版卸载重试失败和安装文件复制失败处。因此用户截图不能单独证明有残留画布进程，也不能证明这次一定由退出竞态引起。截图中的小内存 32 位进程可能是安装器。
- 文件被安全软件等占用、安装目录权限和旧卸载器失败尚未在受影响用户机器复现，不宣称全部安装故障已解决。

## 修复合同

1. 更新先进入 `preparing-install`，复用现有主窗口/主 frame 的保存回执与运行任务检查；拒绝、冲突、运行中或保存超时，不启动安装器，也不关闭后台。重复点击共用同一个请求。
2. 保存批准后保持已有 renderer close hold，等待 `shutdownBackendForElectron('ELECTRON_UPDATE')` 完成后台/存储关闭，再调用原平台更新器。普通关闭不能并发绕过准备阶段，Mac 保留原生 Squirrel 重启流程。
3. 后台关闭超时/异常或安装器启动失败时不自动重试，不撤销已批准的保存 hold 使已停止的后台重新可编辑；明确提示退出后手动安装/必要时重启电脑。准备/安装期间禁止检查或下载替换当前更新；部分关闭后也禁止重新进入更新流程。
4. 新安装器/卸载器使用 electron-builder 支持的 `customCheckAppRunning`，只查询精确主程序文件名。最多正常等待 30 秒，覆盖旧客户端 10 秒保存门和 15 秒后台截止时间并留余量。没有匹配进程才继续；仍在运行或检测异常分别提示，并可重试/取消，不调用强杀。标准 Setup 文件名不匹配主程序名。
5. 使用已有 nsProcess Unicode 插件，不新增下载/运行依赖；按其[官方返回码合同](https://nsis.sourceforge.io/NsProcess_plugin)仅接受 `603` 为未找到，其他错误失败关闭。不扫描、删除或搬运用户数据库/素材，不改变保存、水位或恢复规则。
