# zcanvas 凭据文件的并发更新

2026-10-20，修复已随v3.3.7双平台发布；正式产物见[发布专题](release-v3.3.7.md)。
下文保留源码/临时凭据证据，安装版实配对仍待验收；组合证据见[接管结果](dsh-native-integration-20261020.md)。

旧 secureStore 在读取完整 JSON 后才保护凭据，再写回先前快照。另一进程在
这段时间写入的工作区、审批或会话可能丢失；首次并发创建配方签名密钥也
可能分叉。旧快照直接 writeStore、过期请求的清理还可能覆盖新配对。

现在凭据保护在临界区外完成，实际读改写进入本机文件协调器后重新读取。
存储 JSON 仍是 t8-zcanvas-secure-store-v1，字段、DPAPI entropy 与保护方式
保持；协调信息只在旁边的 .lock / .lock-state，未加入凭据内容。公开
readStore/writeStore 通过返回对象的内存摘要拒绝过期快照；不能用任意克隆
对象无条件覆盖现有文件。首次创建空存储以及同一对象刷新后的继续更新可用。

协调器用硬链接原子发布完整进程/随机标识回执，等待最多2秒（单调时钟）。
活进程从不按文件年龄抢占。已终止进程由唯一恢复标记协调回收，写入方在
进入前同时检查恢复标记和自己的回执身份；已知遗留临时文件按精确回执
清理。候选文件 fsync 后 rename；失败不覆盖旧检查点。损坏或链接侧目录
拒绝写入，文件系统不支持硬链接时不降级成无锁写入。

同实例的不同未过期配对不互相替换；同一请求的元数据保持不变。保存领取的
会话时，pairingId/origin 在事务内再次核对；条件删除也核对原请求/会话。
CLI 的重复配对在发送窗口请求前拒绝；失效会话清理携带身份，Patch 审批
只删除准确的 approvalRequestId。配方签名密钥在事务中只初始化一次。
