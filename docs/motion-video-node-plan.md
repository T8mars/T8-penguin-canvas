# 代码动画节点规划

2026-10-25规划，2026-10-26 P0开发完成，状态及验收见[开发专题](motion-video-development.md)。用户后续已授权v3.4.4打包发布，实际状态见[发布专题](release-v3.4.4.md)。使用标准版 `zhenzhen/motion-video` 与 Pro `zhenzhen/motion-video-pro`，固定贞贞的平价AI小屋渠道。本文保留设计依据；末尾四条API研究是开发前证据，不能与后续完整画布夹具验收混为一谈。

## 决策概要

新增独立“代码动画”节点（类型 `code-animation`），副标题“用文字生成动效视频”。它适合动态文字、片头、产品介绍和数据故事。现有 `video-motion` 是输出文本的运镜提示词工具，不能覆盖。首期不提供任意代码编辑/执行，不承诺源码下载或本地 HTML 渲染，因为官方尚未提供这些协议。

推荐P0交付“文字生成 → 看成片 → 选中版本/段落 → 用自然语言修改 → 保留新旧版本”的完整无图闭环。P1再增加高级图片直链测试功能；普通本地图片连线等持久上传和实际出镜证据齐备后再接入。没有文档依据的关闭配乐、强制无署名、单独免费预览、跨模型修订不做成假开关。

## 用户操作

紧凑节点包含：固定渠道/设置入口、标准版/Pro、动画描述、风格入口、时长/比例/清晰度、更多设置、生成按钮、任务状态、最近成功成片。首次只需填写描述，产品默认建议标准版、15秒、16:9、720p、自动风格；这些是产品选择，不冒认服务端默认。

```text
代码动画                         平价小屋
用文字生成动效视频       [标准版 | Pro]
[描述你的动画……                 放大]
风格 [自动 ▾]
[15秒 ▾] [16:9 ▾] [720p ▾]
[更多设置]                  [生成动画]
--------------------------------------
[视频预览]  [放大] [保存] [修改此版本]
版本 [V2 · 从V1修改 ▾]   [查看分镜]
```

- 放大工作台负责较长描述、模板选择、分镜、版本和对比；节点本体不塞十个输出口或整页高级表单。复用现有 `PromptTextarea`、`LoopingVideo`、Story大窗及编辑版本的交互习惯，不复制 VideoNode 的全部分支。
- 模板按名称/简短说明分组，缺少真实模板成片时只用明确标注“风格示意”的图标与色块，不用假预览。不另设“预览生成”，`preview_ready` 仍是同一任务的中间状态。
- P0更多设置包括标题、副标题、关键词标签、署名、语言、配乐。P1增加最多4个有序持久图片直链，明确为测试功能。关键词回车加一项，可粘贴多行；不按逗号擅自拆分、不去重、不要求JSON。
- 留空的高级字段省略。署名留空意味着交给服务决定，本轮实际出现平台默认署名，不等于“无署名”。语言保留原值，已核实文档 `zh-CN`、本轮使用 `en`；完整语言枚举未证实。配乐只有服务默认/自动配乐 `auto`，不造 `off` 值。
- Prompt/用户文字/模型ID不翻译。没有文档依据不编造标题字数、关键词数量等硬上限；必要的通用传输边界与API限制分别说明。
- 空白节点显示“无需写代码”，提供文字开场、产品介绍、数据故事三个本地示例。选择示例仅填空草稿；已有文字时先预览示例，允许复制/追加，不静默覆盖、不调用额外LLM、不自动运行、不预填署名。生成后用“把某处文字改成……”引导用户修改此版本。

模板静态目录：文字与品牌（`hype-kinetic` 动感文字、`swiss-minimal` 瑞士极简、`cinematic-trailer` 电影预告）；科技与数据（`cyber-glitch` 赛博故障、`blueprint-tech` 蓝图科技、`code-cinema` 代码电影、`data-story` 数据故事）；风格化（`synthwave` 复古合成波、`chalk-hand` 粉笔手绘、`voxel-world` 体素世界）。分组是本地展示，不是新增API字段。“自动”不发送 `template_id`。

## 修订与版本

成片上的“修改此版本”锁定选中版本的成功任务、原输入与渠道配置；不得始终取节点最新任务。修订面板突出独立的修改要求输入，显示基准缩略图和“基于Vn”；创作描述端口含义不变，原Prompt显示为所选版本的只读快照。点击模式/选模板不会提交。修订成功且结果入库后才追加版本，失败、停止、等待中保留旧成片并标注“上一次成功版本”。从旧版本改可以形成分支，历史不能被原地覆盖。

首期沿用基准模型、时长、比例和分辨率；这是已验证范围，不声称服务端永久不支持其他组合。需要变更规格时用“以这些设置新建”回到生成态并清除修订字段。换连接先只读查询原任务，不能付费试探；Key轮换不等于账户变化，查询无权限时本地视频仍可看/保存/新建同款。查询成功只证明可读，不能据此承诺跨账户修订；基准限用户自己的成功任务，提交仍受上游所有权校验。

分镜仅代表该版本服务返回的说明。显示文字、意图、约时长；点击可按累计时长估计跳转，不称精确剪辑。选段生成可编辑的修改要求，例如“将本版本显示CREATE的中间段落（约4.7–9.4秒）改为MAKE，其余段落尽量保持”。版本ID+序号仅用于本地定位，不当作跨版本稳定场景身份；若上游提供场景ID则保留原值，但不猜其稳定性或将它作为未文档化参数。新结果重新解析，不按序号强行匹配旧场景。未返回分镜仍可整片修改。执行文案使用“按修改要求重新生成视频”，不承诺局部无损修改；新旧版分别播放和显示分镜，不能制造精确同步对齐。

普通画布备份遵守现有保真/恢复合同。公开工作流模板不带Key、任务身份、账号关联和产物URL；新建模板导入为新建草稿，修订模板导入为待选择基准的草稿，两者都无运行身份、不自动提交。复制节点不复制进行中任务；显式“从此版本继续”才能携带原版本的修订关系。

## 已核实的协议与适配边界

依据：[官方文档](https://api.seedance.nz/docs/llms.txt) Motion Video章节（本次31813–31847行）；参考项目 `F:/AI-T8-video-onekey/ComfyUI/custom_nodes/ComfyUI_Seedance/skill.md`、`nodes.py:1912`、`core/client.py:1157` 和 `tests/test_motion_video.py`。参考是协议证据，不是T8画布已支持的证明。

| 项目 | 合同 |
| --- | --- |
| 创建/查询 | POST `/v1/video/generations`；GET `/v1/video/generations/{id}` |
| 请求主体 | model、prompt、整数duration（15/30/45/60）、ratio（16:9/9:16/1:1）、resolution（720p/1080p）、可选motion |
| 高级参数 | motion内template_id/title/subtitle/keywords/signature/language/music/assets；空值省略，motion全空则省略 |
| 修订 | motion.revise_from为当前账户自己的已完成任务；revision_instruction为修改要求。生成态完全剔除这两项；查询可读不证明支持跨账户修订 |
| 不发送 | 通用视频seconds、metadata包装、seed、width/height/frames等无合同字段 |
| 图片 | 最多4个持久公开HTTP(S)图片URL；不把本地资源路径、data URL或普通临时上传链接伪装为持久素材 |
| 返回 | 本轮兼容外层data.status；成片在data.data.content.video_url，封面/分镜/fallback在data.data同层。应保留有序完整结果与未知辅助信息的安全边界 |
| 时限 | 共享媒体策略最低15分钟，不能因内部写代码就套用LLM的3分钟上限 |

模板目录实测返回HTTP200但正文 `success=false`、无权限，API Key不具备该目录所需登录权限。内置经核实的目录，不把它作为启动/生成前置依赖。

## 状态、恢复与输出

| 情况 | 用户看到/可以做什么 |
| --- | --- |
| 等待、分镜、编码、检查、媒体生成、渲染 | 有真实阶段才显示对应说明；没有百分比不编造进度/剩余时间。本轮外层主要为QUEUED/IN_PROGRESS/SUCCESS |
| preview_ready | 继续等待最终视频；只有实际返回可访问预览才出现入口，不提交最终输出 |
| 成功且有fallback | “已生成，部分场景使用替代效果”，保留视频及完整替代信息；不冒认完全符合提示，也不丢弃可用成片 |
| 已生成但下载失败 | “视频已生成，保存到本地失败”；重试保存/查询原任务，只GET，不重新生成 |
| 受理不明/等待超时 | 明确结果未确认。有任务ID恢复原任务；没有ID保留受理未知，不自动重发POST |
| 用户停止等待 | 说明服务端可能继续，保留恢复入口；没有取消协议不声称已取消或退款 |

主输出为已落盘视频资产；封面、分镜、fallback随同一版本的结果元数据保存。可选预览/HTML/字幕只在真实返回后处理，首期不在Electron主环境执行上游HTML，不为缺失字段制造空文件。展开复杂原始响应不应占据普通用户流程，诊断要脱敏。

视频完整性是主结果门；坏格式/过大的可选分镜、封面失败只给附属信息不可用提示，不把有效视频整个判失败。解析/显示有本地预算，超限明确说明不完整，不能当作API限制。文本转义、未知结构只按数据展示；链接仅接受合法HTTP(S)，外部打开不带Key，重定向凭据剥离沿共享下载器。公开诊断/模板剥离敏感查询和任务身份，不把整个响应塞进节点。

质量记录分开保存“本次服务报告的替代场景”“基准/祖先降级记录引用”“本版用户审阅状态”。祖先记录不得并入新版当前场景清单；空fallback只能说“本次服务未报告替代场景”，不是“全片正常”。实际Pro修订仍保留原第3场黑底，但新fallback仅列第2场，因此列表不能当作整片完整质量清单。提示旧问题可能尚未改善，并提供旧版本对照，不猜测场景ID一一对应。

## 实施接入点（设计对照，完成情况见开发专题）

P0包含两模型、创建/修订、基本版本列表、只读分镜、真实质量提示和保存/恢复闭环；不拆成只有一个生成按钮就宣称完成。P1为持久图片直链实验和更丰富对照；复杂同步双播放器、视觉差异检测、可编辑时间线不进入P0，本地图片端口与源码编辑保持前述边界。

实施顺序为共享合同/注册 → 账本/查询恢复/结果保存 → 紧凑节点/模板/单播放器大窗 → 修订/版本/分镜 → 真实画布验收/四份模板。完成闭环的最低验收为：正确字段、无重复提交、基准与新任务分离、重启查询原任务、只重试保存、迟到结果不覆盖或复活节点、可用视频和真实降级提示、缺基准零POST，以及画布新建→看结果→选旧版修改→保存重开实操。若后续用户明确授权某些证据后补，逐项保留未验收，不能据此标成已通过。

1. **协议统一**：候选新增共享 `motionVideoContract.json`，集中两模型、枚举、模板与可选字段。`backend/src/providers/seedanceNz.js` 实现严格payload、兼容响应解析及阶段信息；`backend/src/routes/proxy.js` 沿现有Topaz等路径复用提交身份、错误展开与结果materialization，但不能照搬会丢分镜/fallback的通用返回结构。`src/services/generation.ts` 提供typed调用。所有调用用共享超时/可信下载器。
2. **运行恢复**：同步 `src/utils/runRecovery.ts` 与 `backend/src/services/runRecovery.js` 的motion类型、精确模型推断、固定查询路由与video输出识别。`useRunTrigger` 在provider.submitted立即保存descriptor。每次修订是新Run/Attempt/提交键，新taskId用于恢复；原taskId只作输入快照/版本来源。保留幂等键但不据此推断上游保证幂等，不重放受理不明POST。
3. **凭据与身份**：双端恢复descriptor新增非敏感配置引用并测试凭据选择。Key仍由服务端设置读取，不写节点、descriptor、导出或日志。输入快照记operation、基准版本、原规格和revisionInstruction；已受理任务另存原taskId用于只读恢复。
4. **节点与发现**：候选 `CodeAnimationNode.tsx`，同步 `backend/src/shared/canvasNodeSchema.json`、`src/types/canvas.ts`、Canvas映射/默认、`nodePlacement.ts`、中英nodeCatalog。registry/executable清单从共享schema派生，不维护平行名单。同步CLI `creativeCapabilityManifest.json` 并生成能力产物和schema digest。
5. **端口与历史**：一个稳定“创作描述”文本输入；新建时沿现有上游优先、本地备用规则，修订时使用基准Prompt快照，修改要求先由面板独立编辑，端口不随模式改含义。视频为主输出，分镜可通过明确命名的文本输出提供；封面/结构化分镜/质量记录以稳定asset ID关联。检查 `portTypes.ts`、materialSet/upstreamMaterialBuckets、Relay/GroupBox/Output/VideoOutput与下游视频编辑。现有部分透传只枚举已知字段，须验证资产元数据回查，不能假设自动保留。
6. **权限与草稿**：归档/只读禁止新提交和节点写回，仍可看已有结果；沿现有Run/CanvasPatch/实体UID/revision保护，不增加逐次弹窗。运行时冻结输入，后续编辑是下一次草稿。删节点/切画布后的迟到结果不能复活节点或覆盖新实体，结果留在历史。节点、工作台、批量和Agent入口必须一致。
7. **布局和性能**：高级工作台懒加载；模板弹层限于可见视口并内部滚动，末项可达；大窗中部 `min-height:0`、低高度与窄屏适配。视频先封面、点击播放、离屏暂停，关闭工作台清监听/Blob/Observer，不取消共享Run；长版本列表按需显示。保存仅字段和资产引用，不等待视频解码或任务完成；禁止文字滤镜/拖动状态模糊切换。以上是验收要求，不是已测性能收益。
